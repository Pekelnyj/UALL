# Wowhead-конвеєр серверних полів квестів

Витягуємо поля, яких **немає в Blizzard API**: `objectives`, `progress`, `completion`
(+ запасні `title`/`description`). Джерело — сторінки Wowhead.

## Стан на диску (НЕ в чиїйсь пам'яті)

| Файл | Що це |
|---|---|
| `data/source/wowhead_quests.json` | БАЗА: `{questID: {title,description,objectives,progress,completion}}` |
| `data/wh_html_cache/<qid>.html.gz` | **КЕШ сирих сторінок** (~7 КБ/стор, без скриптів). Раз завантажене — назавжди |
| `data/_wh_df_refetch.txt` | список ID на (пере)качку |
| `data/_wh_rf_done.txt` | ID, які вже пробували (щоб не молотити без-цільні по колу) |
| `data/_wh_refetch_status.txt` | ПОТОЧНИЙ прогрес перекачки (читай цей файл замість питати) |

## Ключове правило

**Сторінки кешуються при кожному фетчі.** Тому будь-який майбутній фікс парсера
чи нове поле → **перепарс локально, без жодної перекачки**:

```
python pipeline/reparse_from_cache.py      # оновлює базу з кешу, 0 звернень до мережі
```

Саме цього бракувало, коли загубили objectives (парсер їх не брав, а HTML не зберігали →
довелось качати знову). Тепер такого не станеться.

## Як (пере)качати (анти-бан)

Каденція: бурст 45 + кулдаун 300с (~289/год) — стеля, швидше = 403. Резюмабельно
(перезапуск пропускає готове). Дрип-обгортка сама доводить до кінця й пише STATUS.

```
# перекачати відсутнє objectives (список у _wh_df_refetch.txt):
bash scratchpad/wh_refetch_drip.sh        # або запустити python-цикл із --limit 45

# докачати НОВІ квести (яких ще нема у файлі):
python pipeline/extract_wowhead_quests.py --ids-file <список> --limit 45
```

## Після качки — вмерджити в переклад
`wh_batch_prep.py` (готує партію без-кирилиці) → переклад → `wh_batch_merge.py` →
`generate_db.py` + гейти.
